## 三、性能：这是最大的一块

### 3.1 体积构成

线上 HTML 一共 **3,833,489 字符 / 3.77 MB**，拆开看：

| 内容 | 数量 | 原始体积 | 说明 |
|---|---|---|---|
| 内联 `<script>` | 1 段，3.80 MB | 全部游戏逻辑 | 无法单独缓存 |
| 内联 `<style>` | 1 段 | 22 KB | 正常 |
| base64 图片 | 167 张 PNG | 0.81 MB → 解码后 ~0.61 MB | 全部 base64 塞在 JS 里 |
| base64 音频 | 67 段 MP3 | 2.41 MB → 解码后 ~1.81 MB | 含 24 段配音 |
| **base64 合计** | 234 个 data URI | **3.22 MB（占 84%）** | |
| 纯文本代码 | — | 446 KB | |

压缩后 2.38 MB（Brotli）。**注意：base64 让音频体积凭空多出 33%，而且文本压缩对 base64 几乎无效**——这 2.4 MB 里绝大部分是“本可以懒加载的素材”。

### 3.2 为什么这件事严重

1. **一次全下**：玩家只是打开标题页、还没点“开坛”，就要先下 2.4 MB、解析 3.8 MB 文本、解码 234 个 data URI。手机上这通常是 **3–6 秒白屏 + 明显的内存峰值**。
2. **无法按需加载**：其实你已经有“章节包按需下载”（`ch/xxx.js`）的机制，说明思路是对的，但主包里的素材没走这套。
3. **改一个字，全量重下**：单文件内联意味着改一句台词，浏览器缓存的 2.4 MB 全部失效。
4. **音频是“开场即全解码”**：`loadVoices()` 在播开场剧情时对 67 段音频一次性 `decodeAudioData`。1.8 MB 的 MP3 解成 PCM 后大约 **30–90 MB 内存**（按码率/时长估算），中低端安卓和 iOS Safari 上有卡顿甚至被系统杀掉页面的风险。

### 3.3 缓存策略

| 资源 | 当前 `cache-control` | 问题 |
|---|---|---|
| `/` | `public, max-age=0, must-revalidate` | 每次访问都要回源验证（有 304，可接受） |
| `/share.png` | `public, max-age=0, must-revalidate` | 静态图应长缓存 |
| `/api/scores` | `no-store` | 合理（实时榜单） |

把素材拆成独立文件后，应该给 `assets/*` 配 `max-age=31536000, immutable`，那时首访和回访的差距才会真正拉开。

### 3.4 可预期的收益

| 方案 | 首访传输 | 回访传输 |
|---|---|---|
| 现状 | **2.4 MB** | 304 回源（约 1 个 RTT） |
| 素材外置 + 音频懒加载 + 字体子集化 | **约 200–300 KB**（-90%） | 近 0 |
| 再叠加 PWA 离线缓存 | 首次同上 | **0**（离线可玩） |

这是全部建议里**性价比最高**的一条。

### 4.1 第 2–5 章：UI 在、文件不在

代码里有 5 章（任家镇 / 决战平安京 / 雾都伦敦 / 下南洋 / 地底天宫），第 2–5 章按需从 `ch/<id>.js` 加载。实测：

```

ch/nanyang.js  404

```

默认状态（`CH_LIVE = false`）下章节入口显示“🔒 即将开放，敬请期待”，所以**普通玩家不会遇到 404**，这一点不算线上事故。但只要你用 `?chapters` 调试参数进去，或准备正式开放，这 4 章必然加载失败。**上线前必须把 4 个章节包一起部署。**

### 4.2 生产环境里留了两个“后门参数”

| 参数 | 作用 | 影响 |
|---|---|---|
| `?unlock` | 直接 `localStorage.ztzh_monk = '1'`，解锁隐藏角色“伏魔禅师” | 玩家可自行解锁，等于白给 |
| `?chapters` | 打开章节选择、跳过“未开放”限制 | 调试用，配合 4.1 会 404 |

如果隐藏角色是靠“通关解锁”做长期留存的，`?unlock` 建议改成只在 `localhost` 生效（`location.hostname === 'localhost'`）。

### 4.3 存档

- 全部进度在 `localStorage`（`ztzh_board`、`ztzh_hero`、`ztzh_chap`、`ztzh_story`、`ztzh_name` 等 13 个键）。
- **没有账号、没有云存档**：换手机、清缓存、无痕模式 = 进度全丢，且功德簿上的名字和本机进度是两套东西。
- 没有 `manifest.json`、没有 Service Worker：**不能“添加到主屏幕”，也不能离线玩**。对一个 3.8 MB 单文件游戏来说，PWA 几乎是“顺手就有”的加分项。

## 六、安全与合规

### 6.1 响应头缺失

现在只有 `HSTS`、以及 `api` 上的 `x-content-type-options: nosniff`。缺：

| 头 | 作用 | 影响 |
|---|---|---|
| `Content-Security-Policy` | 限制脚本来源 | 缺失（内联脚本使 CSP 需要 `unsafe-inline` 或 hash） |
| `Referrer-Policy` | 控制 referrer 外泄 | 缺失 |
| `Permissions-Policy` | 关掉不需要的传感器/摄像头权限 | 缺失 |
| `X-Frame-Options` / `frame-ancestors` | 防点击劫持、防被套壳 | 缺失，任何人可 iframe 你的游戏（套壳站、广告站常见） |

对你的场景，**最低成本是加 `X-Frame-Options: SAMEORIGIN` + `Referrer-Policy: strict-origin-when-cross-origin` + `Permissions-Policy: camera=(), microphone=(), geolocation=()`**，一行 `_headers` 文件的事。

### 6.2 第三方依赖

- 唯一外部资源是 **Google Fonts**（`fonts.googleapis.com`，字体 `ZCOOL QingKe HuangYou`），已用 `media="print" onload` 做了非阻塞加载，技巧是对的。
- 但 **Google 域名在中国大陆基本不可达**，字体加载会失败并回退到 `PingFang SC / Microsoft YaHei`，标题的像素感会丢；而且多一次跨域 DNS/TLS。
- 建议：把字体 **子集化成 woff2 自托管**（这个字体只用在标题和少量文案，子集后通常 20–40 KB）。

### 6.3 代码里残留的“来源痕迹”

- `<meta name="claude:viewport-fit-sides" content="cover">`
- `window.claude.use('db')` / `window.claude.use('user')` 分支（在 Netlify 上永远为 `null`，属于死代码）

不影响运行，但公开源码里带着这些没意义，也暴露了制作链路。删掉更干净。

### 6.4 国内访问与备案

站点在 `*.netlify.app` 免费域名上。**netlify.app 在中国大陆的连通性不稳定**（DNS 污染/间歇性不可达是常态），你分享给国内朋友时可能有人打不开。若要长期运营：

1. 绑自有域名（短期靠 Cloudflare 代理改善，但 Cloudflare 免费版在国内也只算“能用”）；
2. 真要做国内用户，需要 **ICP 备案 + 国内对象存储/CDN**，否则随时可能被墙或被服务商下线；
3. 排行榜目前存昵称（弱个人信息），没有手机号/微信，合规压力很小，但接入登录后要补隐私政策。
